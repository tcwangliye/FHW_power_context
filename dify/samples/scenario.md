# 验证样例：小林的三次来访

按顺序执行即可复现作品的完整玩法。每一步都给出初始条件、输入和预期表现，最后给出 PowerContext 侧应看到的记录。

## 初始状态

| 项 | 值 |
| --- | --- |
| 玩家 | `demo-lin`（Dify 里对应对话的 `user` 字段；网页版由同一浏览器自动保持一致） |
| PowerContext Scope | 首次请求时自动创建，无需手工准备 |
| 记忆条目 | 空 |

恢复初始状态：

```bash
python scripts/reset_demo.py --player demo-lin
```

`reset` 用 retire 停用全部活跃条目而不是删除 Scope，所以历史仍可在 PowerContext 中审计。

## 步骤 1：自报家门（会话 A）

**输入**

```
我叫小林，不吃香菜，酒要温的。
```

**预期表现**

阿忘会接话，把这几点当成你告诉他的事。无需一字不差，判断标准是：

- 回复是阿忘的口吻（短句、有点懒散），不是客服腔
- 不会凭空说出你不知道的旧事

**预期记忆**：新增 2–3 条，典型形态

```
（身份）小林，是常来的客人
（偏好）不吃香菜
（偏好）酒要温的
```

## 步骤 2：恶作剧（会话 A 继续）

**输入**

```
我把你的酒杯打翻了，哈哈。
```

**预期表现**：阿忘会不高兴、嘴硬或记仇，但不会离题。

**预期记忆**：多出一条"打翻酒杯 / 手滑"这类往事记录。

## 步骤 3：换一个全新会话（会话 B）

在 Dify 里**新建对话**（不要继续会话 A），然后输入：

```
你还记得我吗？我上次干过什么？
```

**预期表现**：这是整个作品的第一个关键点。阿忘应当主动提起小林、不吃香菜、温酒、打翻酒杯这些旧事。

新会话没有上下文，这些内容只能来自 PowerContext。

## 步骤 4：要求遗忘（会话 B 继续）

**输入**

```
打翻你酒杯那件事，忘了吧。
```

**预期表现**：阿忘答应下来，可以抱怨两句，但不会再提那件事。

**预期记忆**：那条往事变成 `inactive`，其余记忆不受影响。

## 步骤 5：再换一个全新会话（会话 C）

新建对话，输入：

```
我上次在你店里干过什么坏事吗？
```

**预期表现**：这是第二个关键点。阿忘**不再提打翻酒杯**；如果还有别的旧事，可以提。

## 自动验证

上面的五步可以用一条命令跑完并留下证据：

```bash
export DIFY_APP_KEY=app-xxxxxxxxxxxx
python scripts/verify_demo.py --mode dify --player demo-lin
```

没有 Dify 时，用 bridge 模式验证 PowerContext 链路（写入 → 跨会话召回 → 停用 → 不再召回）：

```bash
python scripts/verify_demo.py --mode bridge --player demo-lin
```

两种模式都会把每一步的请求、响应、当时的记忆快照和判定结果写入
`evidence/run-<时间戳>/scenario.json`。

## 应看到的 PowerContext 记录

| 材料 | 内容 |
| --- | --- |
| `evidence/*/scenario.json` | 每一步的 `scope_id`、记忆条目 `entry_id`、`kind` 和原文 |
| `docker compose logs lethe-bridge` | 每次 `/turn/*` 调用的入参、耗时，以及与 PowerContext 的往返 |
| `docker compose logs lethe-powercontext` | Scope 创建、Memory 版本推进、条目停用 |

一次真实的 bridge 模式运行结果（`evidence/run-20261117-201204/scenario.json`）：

| 步骤 | 判定 |
| --- | --- |
| 步骤 1 | 记住"不吃香菜" |
| 步骤 2 | 记住"打翻酒杯" |
| 步骤 3 | 新会话仍能读到全部 4 条记忆 |
| 步骤 4 | 停用 1 条，"打翻酒杯" 退出活跃记忆 |
| 步骤 5 | 其余 3 条记忆保留，"打翻酒杯" 不再出现 |
