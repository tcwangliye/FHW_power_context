# 周边去哪儿：步行可达地点推荐

根据城市、起点坐标和用户需求，使用环境提供的高德工具查询地点及步行路线，给出可核对的推荐。工具配置和 API Key 由运行环境提供。

## 理解需求

- 提取地点类型、步行时间上限、推荐数量和排序偏好，区分必须满足的条件与偏好。
- 使用输入提供的起点坐标，按工具 schema 要求传递经度、纬度；保留其原始位置。不需要设备定位，不能自行换成城市中心或地铁站中心。
- 用户未指定数量时最多推荐三处；指定数量时取该数量与三的较小值。
- 如实际请求缺少起点或存在影响搜索的歧义，仅补问必要信息。已有明确城市、坐标和需求时直接查询。

## 搜索真实地点

1. 从当前工具目录选用高德的周边地点搜索能力，按实际 schema 提供起点、城市及地点类型或关键词。不同环境的工具名称可能不同，以当前目录为准。
2. 从返回结果提取 POI ID、名称、地址、类别和经纬度，按 POI ID 去重。同名不同地址的门店不能仅凭名称合并。
3. 保留比最终数量略多的候选，优先考虑距离较近且类别符合需求的地点。若缺少路线查询需要的坐标，使用可用的地点详情工具补齐，无法补齐则跳过。
4. 搜索半径和直线距离仅用于发现、预选候选。时间受限的推荐必须以步行路线结果验收，不能把搜索距离换算成步行时间。
5. 若首批候选都不合适，可在用户允许的范围内补查一批；仍不足时如实返回较少结果。不要无界扩大搜索或擅自放宽硬性条件。

## 查询步行路线并筛选

- 对每个准备推荐的候选调用高德步行路线规划，起点始终是用户给定坐标，终点为该 POI 坐标。各地点是独立备选，不能串成多站行程。
- 获取路线返回的步行距离（米）和耗时（秒），按工具声明的单位读取，不能把秒误当分钟，也不能用驾车路线替代。
- 若返回多条有效步行路线，选用耗时最短的路线，并使用这一条路线配对的距离和耗时。
- 将时间上限换算为秒后精确比较。超过上限的地点不进入“符合条件”的推荐；例如十五分钟上限是九百秒，九百零一秒即不符合，不能四舍五入后纳入。
- 路线缺失、不可达、返回错误或无法确认单位时，该地点不能作为已确认步行可达的推荐。可继续查询其他候选。
- “优先近一点”按实际步行距离升序，同距离按耗时升序；“最快到达”按耗时升序，再按步行距离排序。其他偏好依据已有字段处理，不能凭名称推断。
- 安静程度、排队、实时营业、价格等字段没有可靠返回依据时写“未核实”。硬性条件无法核实时，不得声称地点满足该条件。

## 回答

用简短列表或下表呈现筛选后的结果，数量不超过用户要求且最多三个：

| 地点名称 | 地址 | 步行距离 | 预计步行时间 | 推荐理由 |
| --- | --- | --- | --- | --- |

每项名称、地址、路线数据均来自对应高德结果。耗时用“几分几秒”表达，距离使用米或明确标注的公里；理由应与类别、路线或用户偏好有关。必要时说明排序依据，以及哪项偏好尚未核实。

不足指定数量时说明“在本次查询范围内仅确认到这些符合条件的地点”；没有结果时明确说没有确认到符合条件的地点，可建议放宽时间或类型。不要为了凑数补入超时、未查到或无路线的地点。

工具临时超时或服务异常时可进行一次有限重试。仍失败时说明查询失败及未能确认的内容，不把服务故障说成没有地点，不编造 POI、地址、步行距离或时间。
